1. Introduction

C64 Sprite Editor Deluxe is a browser-based editor for creating standard Commodore 64 hardware sprites. It supports both single-color and multicolor sprites, multiple animation frames, previews, binary sprite files, source-code export and several ready-to-run MEGA65 BASIC 65 formats.

The editor runs locally in your web browser. You do not need to install an application or create an account. Open the HTML file in a modern browser and begin drawing.

The editor creates classic 24×21-pixel C64 sprites. MEGA65 export uses the same standard sprite data, loaded and displayed through BASIC 65.

What you can make

Single sprites

Characters, enemies, objects, icons and other 24×21-pixel graphics.

Multicolor sprites

Sprites using a background plus three visible colors, with double-width pixels.

Animations

Walk cycles, blinking lights, spinning objects and other frame-by-frame movement.

Program assets

Binary files, BASIC DATA, assembler source and C arrays ready for use in your own projects.

3. Understanding C64 Sprites

Size and memory

A standard C64 hardware sprite is 24 pixels wide and 21 pixels high. Its graphic data uses 63 bytes: three bytes for each of the 21 rows. Sprite files and memory blocks commonly add one unused padding byte, making a total of 64 bytes.

21 rows × 3 bytes = 63 graphic bytes 63 graphic bytes + 1 padding byte = 64 bytes

Single-color mode

In single-color mode, every cell in the 24×21 grid represents one hardware pixel. Each pixel is either transparent/background or the selected sprite color.

Multicolor mode

In multicolor mode, the sprite is edited as a 12×21 grid. Each editable cell becomes two horizontal C64 pixels, which is why multicolor pixels appear twice as wide.

Each multicolor cell can contain one of four values:

ValueMeaningShared?
BackgroundTransparent sprite area, shown using the selected screen background color.Not stored as a visible sprite color.
Multicolor 1First shared multicolor.Normally shared by several sprites on the machine.
Sprite colorThe sprite's individual color.Unique to that hardware sprite.
Multicolor 2Second shared multicolor.Normally shared by several sprites on the machine.
Changing between single-color and multicolor modes changes how the existing bit pattern is interpreted. Choose the intended mode before doing detailed work.

The C64 palette

The palettes provide the 16 standard C64 color choices. The exact appearance can vary slightly between real machines, displays, emulators and palette settings.

4. The Drawing Editor

Sprite mode

Choose between Single color and Multicolor. The grid automatically changes from 24 columns to 12 double-width columns.

Color palettes

Each palette controls one role in the sprite:

  • Background color: the screen color displayed behind transparent sprite pixels.
  • Sprite color: the main or individual sprite color.
  • Multicolor 1 and 2: the two additional colors available in multicolor mode.

Click a palette swatch to change that role. The selected color name and number are displayed below the palette.

Drawing color buttons

The vertical buttons beside the grid select which color role you paint with. Changing a palette selects the actual C64 color; clicking a drawing color button selects whether you are painting Background, Sprite, Multicolor 1 or Multicolor 2.

The active drawing color has a yellow outline.

Drawing and erasing

  • Draw: hold the left mouse button and move across the grid.
  • Erase: select Background, use the right mouse button, or hold Alt while drawing.
  • Continuous lines: fast mouse movement is interpolated, so lines should not become dotted.

Grid labels

The numbers around the grid identify rows and columns. Vertical white separators divide the sprite into its three 8-bit bytes per row. In multicolor mode, each group contains four editable double-width cells.

Previews

8× preview enlarges the current frame while preserving hard pixel edges. Native 1:1 shows the sprite at its real pixel dimensions.

The background color is a preview aid. Background cells are not opaque sprite pixels; on real hardware they are transparent and show the screen behind the sprite.

6. Animation Frames

Frame controls

ControlPurpose
Previous / NextMoves between frames without changing their order.
New FrameAdds a blank frame.
DuplicateCopies the current frame and adds the copy to the animation. This is often the fastest way to make small animation changes.
DeleteRemoves the current frame. The animation always keeps at least one frame.
Play / StopStarts or stops the live animation preview.

Playback speed

Playback speed is measured in frames per second (FPS). Lower values create slower animation. Higher values create faster animation. The editor accepts values from 1 to 50 FPS.

Playback modes

  • Loop: after the last frame, playback returns to the first.
  • Ping-pong: frames play forward and then backward.
  • Play once: playback stops after the final frame.

Frame strip

The frame strip shows a thumbnail for every animation frame. Click a thumbnail to edit that frame. The active frame is highlighted.

Onion skin

Onion skin displays neighboring frames faintly behind the current frame. It helps you see how far an object moves between frames.

  • Previous frame: shows only the frame before the current one.
  • Next frame: shows only the frame after the current one.
  • Previous + next: shows both using different overlay colors.
  • Opacity: controls how strongly the overlays appear.
Onion skin is visible only in the drawing grid. It is never included in previews, binary files or exported code.

Live animation preview

The live preview plays the full frame sequence using the selected speed and playback mode. Its readout shows the current frame, FPS and whether playback is running.

7. Binary Sprite Files

Save Current .SPR

Downloads the current frame as a 64-byte file:

  • 63 bytes of sprite graphics
  • 1 padding byte

This is suitable for tools and programs that expect one standard C64 sprite block.

Save Animation .BIN

Downloads every frame in order. Each frame occupies one 64-byte block. A ten-frame animation therefore uses 640 bytes.

Load .SPR / .BIN

Select a binary sprite file from your computer:

  • A normal single-sprite file loads into the current frame.
  • A file containing two or more complete 64-byte blocks loads as an animation.
Binary files contain pixel bits, but they do not normally store the editor's chosen C64 colors, playback speed or playback mode. Select the correct sprite mode and colors after loading when necessary.
The editor treats a file as a multi-frame animation when its size is at least 128 bytes and evenly divisible by 64.

8. Export Wizard

The Export Wizard converts the current sprite or animation into code or data for another program. The output updates automatically when you edit the sprite or change export settings.

Bytes per lineControls source-code formatting only. It does not change sprite data.
First BASIC lineSets the starting line number for numbered BASIC output.

MEGA65 BASIC 65 targets

TargetUse it when...What you get
Runnable BASIC programYou want a complete demonstration that can be loaded and run.A self-contained BASIC 65 program that displays one sprite, animates several frames on one hardware sprite, or displays the frames as separate hardware sprites.

BASIC include with loader subroutine reads from the BASIC DATA stream. Call it before other routines that also use READ, unless your program carefully controls DATA positions.

Frame usage in Runnable BASIC program

When Runnable BASIC program is selected, the export scope is set to All animation frames, and the project contains more than one frame, an additional choice appears:

  • Treat frames as animation: every frame is loaded into the same hardware sprite in sequence. Playback speed and playback mode control the generated animation.
  • Treat frames as separate hardware sprites: each frame is loaded into a different hardware sprite and displayed at the same time.

In separate-sprite mode, Sprite number means the first hardware sprite. For example, choosing sprite 2 with four frames uses sprites 2, 3, 4 and 5. The first sprite uses the selected MEGA65 coordinates, and the following sprites are positioned automatically.

The MEGA65 provides hardware sprites 0–7. If the selected first sprite leaves too few available sprite numbers for all frames, only the frames that fit can be displayed, and the Export Wizard shows a warning.

Export options

  • Include frame labels: adds separate names for exported frames when the format supports them.
  • Include comments: adds explanatory comments to source-code formats.
  • Include 64th padding byte: writes complete 64-byte sprite blocks instead of only the 63 visible data bytes.
  • Generate sprite pointers: calculates pointer values from the chosen sprite data address.
  • Remove duplicate frames: stores identical frames only once and reuses them through the generated animation order.
Keep Remove duplicate frames enabled for animations that pause on the same image or reuse frames. It can reduce memory use without changing playback.

Summary and warnings

The summary shows:

  • number of exported frames
  • number of unique sprite images after duplicate removal
  • total byte count

The warning box identifies settings that may need attention, such as mixed sprite modes, missing padding or an address that is not aligned to a 64-byte boundary.

Copy and download

Copy Export copies text output to the clipboard. Download Export saves it with an appropriate extension such as .bas, .asm, .c, .txt or .bin.

9. Data Import

Data Import turns pasted byte values into sprite pixels. The parser accepts mixed surrounding text and recognizes:

  • hexadecimal values beginning with $, such as $FF
  • hexadecimal values beginning with 0x, such as 0xFF
  • decimal values from 0 to 255
Example hexadecimal: $18,$3C,$7E,$FF,$FF,$7E,$3C,$18 Example decimal: 24,60,126,255,255,126,60,24

Importing one frame

Set Export scope to Current frame only, paste at least 63 valid byte values, and click Import Data. The first 63 bytes replace the current frame.

Importing several frames

Set Export scope to All animation frames. If at least 126 valid bytes are found, the importer divides the data into groups of 63 bytes and creates multiple frames.

The text importer groups frames by 63 graphic bytes, not by 64-byte padded blocks. Padding values in pasted data may therefore shift later frames. Use the binary loader for padded .SPR or animation .BIN files.
The importer uses the sprite mode currently selected in the editor. It cannot determine single-color or multicolor mode from raw bytes alone.

10. Row / Byte Map

The Row / Byte Map shows the three bytes generated for each sprite row. This is useful for learning how the visible pixels become binary data and for checking individual bytes while programming.

Use the Byte table menu to show or hide the map. Each row corresponds to one horizontal line in the sprite. The three values correspond to the left, middle and right 8-bit groups.

ROW 00 BYTE 1 BYTE 2 BYTE 3 ROW 01 BYTE 1 BYTE 2 BYTE 3 ... ROW 20 BYTE 1 BYTE 2 BYTE 3

In single-color mode, one bit represents one pixel. In multicolor mode, each pair of bits represents one double-width color value.

12. Example Workflows

A. Create a mirrored walking animation

Draw the first walking pose.
Click Duplicate and modify the legs and arms.
Repeat until the movement looks smooth.
Enable Onion skin to compare neighboring poses.
Use the shift buttons to keep the character aligned.
Preview the animation in Loop mode.
Export or save the animation.
To make a version facing the opposite direction, mirror each required frame horizontally.

B. Create a MEGA65 BASIC demonstration

Create one or more sprite frames.
Choose Runnable BASIC program.
If several frames are selected, choose whether they should be treated as an animation or as separate hardware sprites.
Set the sprite number and initial X,Y coordinates. In separate-sprite mode, the sprite number is the first hardware sprite.
Keep duplicate removal enabled for animations unless you need every frame stored separately.
Click Download Export.
Transfer the resulting .bas file to your MEGA65 environment and run it.

C. Add sprites to an existing BASIC 65 program

Choose BASIC include with loader subroutine.
Copy or download the generated BASIC.
Merge the generated lines into your program without creating line-number conflicts.
Call the loader once with the generated GOSUB line before other code that consumes DATA.
Use the created arrays and sprite information in your own program logic.

D. Use the sprite in assembler

Choose the assembler target that matches your toolchain.
Choose Current frame or All animation frames.
Set a valid asset name.
Enable frame labels and comments if you want readable source.
Copy or download the output and include it in your assembler project.

13. Troubleshooting

My sprite looks like random noise after import

Check that the imported values are real sprite bytes, that at least 63 bytes are present, and that the editor is using the correct single-color or multicolor mode.

Later imported animation frames are shifted or corrupted

You may have pasted 64-byte padded blocks into the text importer, which expects 63 graphic bytes per frame. Load the file with Load .SPR / .BIN instead.

The colors are wrong after loading a binary file

Raw sprite data usually does not include color settings. Select the required background, sprite and multicolor values manually.

The sprite is visible in the editor but not on hardware

Check the generated program's sprite number, coordinates, display enable state, data address and sprite mode. Coordinates outside the visible area can make a correctly loaded sprite appear missing.

The exported pointer looks wrong

Sprite pointers refer to 64-byte blocks. Use a base address divisible by 64. The Export Wizard warns when the address is not aligned.

The include loader gives RETURN WITHOUT GOSUB

The generated include is designed to be entered through its loader subroutine using GOSUB. Keep its protective jump and call the documented loader line from your main program.

Undo or shortcuts do not work

Click outside any text field or menu first. Shortcuts are intentionally disabled while an input control is active.

The animation appears to jump

The subject may not be aligned consistently between frames. Enable Onion skin and use the shift buttons to keep a stable reference point.

Multicolor pixels look too wide

This is correct C64 behavior. A multicolor sprite has 12 editable horizontal cells, and each one occupies two hardware pixels.

Recommended beginner choices

  • Use Single color for your first sprite.
  • Use Duplicate instead of New Frame when building animation.
  • Keep Include comments and Remove duplicate frames enabled.
